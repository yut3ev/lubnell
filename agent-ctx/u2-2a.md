## API contract — `POST /api/admin/pages`
Auth: admin cookie `lubnel_admin_session` or `x-admin-token` header; permission `pages.write` (unchanged pattern).

```jsonc
// request
{ "action": "seed-defaults" }
// response 200
{ "ok": true, "success": true, "added": 7, "pages": [ /* full list incl. seeded */ ] }
// idempotent second call → added: 0. Customized pages are never overwritten.
// save now accepts optional: { "action":"save", slug, titleAr, contentAr, titleEn?, contentEn? }
```
Seeded entry shape: `{ slug, titleAr, contentAr, titleEn, contentEn, updatedAt }` stored in StoreSettings key `pages` (JSON array) — same shape the storefront renderer and old CRUD already read.

## Known limitations
1. **Unknown-slug HTTP status is 200 (not 404)** while the not-found UI does render client-side. Root cause: `(store)/loading.tsx` streams the shell before the async page throws `notFound()`, so the status is already flushed — pre-existing behavior for every async page under `(store)` (products/cart included), not introduced here. Proper fix (drop/replace loading.tsx or stream 404s) is global and belongs to task 2-d (SEO) — flagging for integration.
2. Admin pages editor stores plain text; per-page rich HTML/markdown is out of scope. FAQ accordion works with the "سؤال\nجواب" convention (seeded + ≥2 pairs), otherwise prose fallback.
3. Contact/shipping structured panels (CTA, regions, steps, fees) are built-in data, not admin-editable fields — the narrative text around them is editable. Fees/regions reflect the audited constants (60 EGP, free ≥900); wiring them to future `store` settings keys would be a follow-up.
4. EN rendering of info pages is client-side via `useT()` (consistent with the site's client-side lang toggle); crawlers index the Arabic-first SSR layer (`generateMetadata` is AR-first as specified).
5. Cross-link strip at the bottom of info pages shows bilingual labels ("AR · EN") since it is server-rendered outside the client lang context.
